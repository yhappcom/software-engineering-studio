## SOURCE

Current Flutter integration-test documentation states that integration tests run on physical devices or OS emulators and documents `flutter test integration_test/app_test.dart` for Android-device execution. Flutter's testing overview explicitly distinguishes integration tests on an OS emulator/device from host/widget tests.

Primary sources checked 2026-09-20:
- https://docs.flutter.dev/testing/integration-tests
- https://docs.flutter.dev/testing/overview

The Android-emulator CI harness uses `reactivecircus/android-emulator-runner@v2`; its current action documentation describes installing/configuring an AVD, booting it, waiting for readiness and running a supplied script. This third-party action is infrastructure, not the semantic oracle.

## CLAIM / TEST EVIDENCE CONTRACT

**CLAIM:** a minimal Flutter state transition can compile, install and execute through a real Android application/integration-test boundary on an Android Emulator, rather than only the host `flutter_test` runtime or Chrome test target.

**SPEC/PROPERTY:** initial visible state is `0`; tapping the keyed increment control must cause Flutter state mutation/rebuild and visible state `1`.

**TARGET:** an isolated app generated by `flutter create --platforms android` inside CI, using the Flutter stable checkout recorded by the run.

**ORACLE:** `integration_test` + `flutter_test` assertions observe `0`, perform the tap, settle, then independently assert `1`. CI success additionally requires app build/install/test process completion.

**ENVIRONMENT identity recorded by workflow:** Flutter machine version, Flutter git HEAD, Dart version, `flutter doctor -v`, Android release/API/ABI, `flutter devices`, runner/job identity.

**FAILURE MODEL:** catches inability to create/build/install/launch the Flutter Android target, device-discovery failure, integration-test binding failure, and failure of the bounded widget state transition in the Android app process. It does not exercise process death, permissions, platform channels, background execution, storage, release signing, physical hardware or product code.
